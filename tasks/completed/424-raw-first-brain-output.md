## Source Context

## Goal

Guarantee that Hands can always read the complete raw output generated by Brain, including the complete XML block when one exists, without allowing malformed XML to become executable.

## Blueprint Reference

Seven-seat brainstorm artifact: `tasks/.sessions/ses_df6723727ffeyqIEuj01fTgRgS_8777faaf/brain_outputs/chatcmpl_125498a5_6293_4c81_bd1d_bb03fe6f8ca24dea9801c4133d8419bf.json`. Manager selected D1: O3 raw-first hybrid.

## Manager's Notes

- Verbatim goal: "agents always see the entire XML the brain generated. or if no xml, see entire output the brain generated."
- Manager proposed removing bridge extraction and letting the agent use Python. Brainstorm rejected ad-hoc Python parsing as non-deterministic and unsafe for control payloads.
- Selected architecture: persist raw provider output before triage; keep extraction advisory; expose one deterministic shared parse/validate helper for Hands; execute only complete validated blocks.
- Observed failure: provider completed normally with 7,175 output tokens, but strict reject replaced the ~23 KB raw answer with a 2,000-character preview before artifact and transcript persistence. The raw answer became unrecoverable.
- Standing rule saved to `architecture/brain-raw-output-completeness`.

+

+
+The bridge captures immutable provider text before XML extraction, semantic validation, and hint or reject rewriting.
