## Goal

Add a new section to the Prompt Composer HTML tool (`tools/prompt-composer/index.html`) where the user can paste a context report Markdown file generated by the Hands (from `context-reports/`), plus a ready-to-use preset Manager message instructing the Orchestrator to review the provided context report — mirroring the existing Task Discovery / Collect Context preset pattern. The pasted report must be included in the generated Markdown output as a dedicated section so the Orchestrator receives the gathered context inline.

- The ready-to-use message should be a new preset button alongside the existing ones (Task Discovery, Collect Context, Approved, etc.) with wording like "the context report provided, please review it."
- Use the `prompt-refactor` skill output (below) as the authoritative implementation instruction, and keep the tool's single-file vanilla-JS architecture.

## AI Analysis & Opinion

The Prompt Composer already bridges the Brain↔Hands workflow: Task Discovery and Collect Context presets tell the Hands to *gather* context reports, and the Project Tree section lets the user pass a tree inline. The missing link is the **return leg**: once the Hands produces `context-reports/context_report_*.md`, the Manager has no structured slot to feed that report to the Orchestrator — they must inline it into the Manager Message manually.

1. **Placement:** A "Context Report" section between Project Tree and Task File mirrors the data flow (tree → report → task) and keeps the numbering intuitive (5. Context Report, 6. Task File, 7. Output, or renumber as the implementer sees fit).
2. **Conditional output:** Reusing the exact Project Tree pattern — emit `# Context Report` only when non-empty — keeps the generated Markdown clean for users who don't use reports.
3. **Preset message:** The new preset should make the Orchestrator consume the report as authoritative context before planning (e.g., "A context report is provided in the Context Report section. Review it in full before generating any task or blueprint — it contains the authoritative project context gathered by the Hands.").
4. **Backward compatibility:** Low risk — purely additive (one textarea, one button, one conditional block in `generateMarkdown()`). No existing behavior changes.
5. **Risk:** Minimal. No new dependencies; localStorage/quota not involved; the report content is plain Markdown text pasted into a textarea.
