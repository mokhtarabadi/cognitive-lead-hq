# Cognitive Lead AI HQ — Global Auto-Configuration for AI Agents

You are an AI agent that has just been given access to this repository. Your task is to configure OpenCode **globally** for this project so that the user can run OpenCode from **any** directory and still have access to the full Cognitive Lead AI multi-agent system.

## System Instruction

You MUST execute the following steps in order. Do NOT skip any step.

---

## 1. Verify Prerequisites

Check that the following tools are installed:

- **Git** — to clone the repository
- **uv** — fast Python package manager (required by the MCP servers)

### Installing uv (if missing)

If `uv` is not found, ask the user:

> "uv is required to run the MCP servers. I can install it for you. Do you approve?"

If the user approves, install uv:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Then add uv to your PATH and continue.

---

## 2. Clone the Repository to a Temporary Location

Clone the Cognitive Lead AI HQ to `/tmp/` so the global installation can proceed without depending on the current working directory:

```bash
git clone https://github.com/mokhtarabadi/cognitive-lead-hq.git /tmp/cognitive-lead-hq
cd /tmp/cognitive-lead-hq
```

All subsequent file operations will reference paths under `/tmp/cognitive-lead-hq/`.

---

## 3. Discover the Home Directory

Resolve the user's home directory. On macOS/Linux this is `$HOME` or `~`. You will need the **absolute path** (e.g., `/home/user` or `/Users/user`) for the global config.

```bash
echo "$HOME"
```

Store this value — you will use it to construct absolute paths in the global config JSON.

---

## 4. Create Global Directories

Create the global OpenCode directories:

```bash
mkdir -p ~/.config/opencode/mcp-context-server
mkdir -p ~/.config/opencode/mcp-memory-server
mkdir -p ~/.config/opencode/mcp-lint-server
mkdir -p ~/.config/opencode/skills
```

---

## 5. Copy MCP Servers and Make Them Executable

Copy both MCP server scripts from the cloned repo:

```bash
cp /tmp/cognitive-lead-hq/mcp-context-server/server.py ~/.config/opencode/mcp-context-server/
cp /tmp/cognitive-lead-hq/mcp-memory-server/server.py ~/.config/opencode/mcp-memory-server/
cp /tmp/cognitive-lead-hq/mcp-lint-server/server.py ~/.config/opencode/mcp-lint-server/
chmod +x ~/.config/opencode/mcp-context-server/server.py
chmod +x ~/.config/opencode/mcp-memory-server/server.py
chmod +x ~/.config/opencode/mcp-lint-server/server.py

# Preserve system-prompt.md globally for the user's Orchestrator
cp /tmp/cognitive-lead-hq/system-prompt.md ~/.config/opencode/system-prompt.md

# Vendor the non-interactive shell strategy globally (instructions file)
cp /tmp/cognitive-lead-hq/docs/opencode-shell-strategy.md ~/.config/opencode/opencode-shell-strategy.md
```

---

## 6. Install Agent Skills Globally

Copy all reusable skills from `skill-templates/` into the global OpenCode skills directory:

```bash
cp -r /tmp/cognitive-lead-hq/skill-templates/* ~/.config/opencode/skills/
```

After this, the skills will be available via `/help` from any directory.

---

## 6.5. Install Custom Agents Globally

Create the global agents directory and copy the custom OpenCode agents from the cloned repo:

```bash
mkdir -p ~/.config/opencode/agents
cp /tmp/cognitive-lead-hq/agents/cognitive-executor.md ~/.config/opencode/agents/
cp /tmp/cognitive-lead-hq/agents/cognitive-discovery.md ~/.config/opencode/agents/
```

After this, the `cognitive-executor` will be available as a primary agent, enforcing ZAC and strict workflow protocols.

---

## 7. Configure Global opencode.json (with Absolute Paths)

Create or update `~/.config/opencode/opencode.json`. You MUST use **absolute paths** in the `command` array — resolve the `~` to the full home directory path discovered in Step 3.

Write the following JSON (replace `$HOME` with the actual home directory path):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "cognitive-executor",
  "instructions": ["$HOME/.config/opencode/opencode-shell-strategy.md"],
  "mcp": {
    "custom_context": {
      "type": "local",
      "command": ["uv", "run", "$HOME/.config/opencode/mcp-context-server/server.py"],
      "enabled": true,
      "timeout": 15000
    },
    "project_memory": {
      "type": "local",
      "command": ["uv", "run", "$HOME/.config/opencode/mcp-memory-server/server.py"],
      "enabled": true,
      "timeout": 15000
    },
    "lint": {
      "type": "local",
      "command": ["uv", "run", "$HOME/.config/opencode/mcp-lint-server/server.py"],
      "enabled": true,
      "timeout": 15000
    }
  },
  "permission": {
    "custom_context_*": "allow",
    "project_memory_*": "allow",
    "lint_*": "allow",
    "lint_markdown": "allow",
    "lint_task_file": "allow",
    "lint_all_tasks": "allow",
    "store_memory": "allow",
    "delete_memory": "ask",
    "read_memory": "allow",
    "search_memory": "allow",
    "list_namespaces": "allow",
    "get_directory_tree": "allow",
    "read_source_files": "allow",
    "external_directory": {
      "*": "ask",
      "/tmp/**": "allow"
    }
  }
}
```

**Important:** Replace `$HOME` with the actual absolute path resolved in Step 3 (e.g., `/home/alice` or `/Users/alice`). This is critical — MCP servers will NOT work with relative paths or `~` in the global config because OpenCode may be invoked from any working directory.

## 7.5. (Optional) Freebuff Support

> **Dual-runtime support.** Since v8.4.5 `system-prompt.md` is runtime-agnostic ("the Hands", `<hands_*_task>` blocks), so this step makes the same tooling — MCP servers, Skills, custom agents, and global rules — work in Freebuff sessions. It does NOT alter the OpenCode workflow.

Freebuff (freebuff.com, vendor: manicode, formerly Codebuff-based) does not read `opencode.json`. It discovers MCP servers, Skills, and custom agents from `.agents/` folders (global: `~/.agents/`) and reads home-directory rules files (`~/.AGENTS.md`, `~/.knowledge.md`, `~/.CLAUDE.md`). Ask the user whether they want this optional step; if they decline, skip it.

Create the global Freebuff directory and write the MCP config (absolute paths only):

```bash
mkdir -p ~/.agents/skills

cat > ~/.agents/mcp.json <<'EOF'
{
  "mcpServers": {
    "custom_context": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "$HOME/.config/opencode/mcp-context-server/server.py"]
    },
    "project_memory": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "$HOME/.config/opencode/mcp-memory-server/server.py"]
    },
    "lint": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "$HOME/.config/opencode/mcp-lint-server/server.py"]
    }
  }
}
EOF
```

**Important:** Replace `$HOME` with the actual absolute path discovered in Step 3 — Freebuff resolves these paths from any working directory, so `~` is not safe here.

Install all 29 Agent Skills globally for Freebuff:

```bash
cp -r /tmp/cognitive-lead-hq/skill-templates/* ~/.agents/skills/
```

Install the custom agent ports (model-free, free-tier compatible) and the global rules file:

```bash
cp /tmp/cognitive-lead-hq/freebuff/agents/cognitive-executor.ts ~/.agents/cognitive-executor.ts
cp /tmp/cognitive-lead-hq/freebuff/agents/cognitive-discovery.ts ~/.agents/cognitive-discovery.ts
cp /tmp/cognitive-lead-hq/freebuff/AGENTS.global.md ~/.AGENTS.md
```

> **Custom agents work on the free tier (v1.2.0):** the ports are **schema-validated** against the Codebuff
> 17-tool platform whitelist (`toolNames` pruned to valid platform tools, `spawnableAgents` in
> `publisher/name@version` format) and **model-free** (`model` omitted so the runtime falls back to the
> free-mode default model, fixing the earlier HTTP 403 `free_mode_invalid_agent_model`). The **live
> free-tier spawn is a manual verification item** pending Manager confirmation — see `docs/freebuff-support.md`
> §5 for the caveat, status, and full port record. The system prompt is used manually — paste
> `system-prompt.md` into any Freebuff chat as the Orchestrator Brain; it emits `<hands_*_task>` blocks
> that run in Freebuff or OpenCode.
